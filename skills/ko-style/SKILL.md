# 한국어 문체 점검

이 스킬은 이미 쓰인 한국어 글을 대상으로 한다. 대화 중의 답변은 Stop hook 이 자동으로 검사하므로 여기서 다룰 필요가 없다.

## 무엇을 세는가

## 점검만 할 때

아래 경로는 이 스킬 디렉터리 기준이다. 절대 경로가 필요하면 스킬 본문 앞에 붙어 오는
기준 디렉터리를 쓰거나 `${CLAUDE_PLUGIN_ROOT}/skills/ko-style/` 를 앞에 붙인다.

```bash
python3 scripts/ko_style_check.py <파일>
cat <파일> | python3 scripts/ko_style_check.py --json
```

위반이 없으면 0, 있으면 1 로 끝난다.

## 고칠 때

1. 검사기를 돌려 무엇이 몇 건인지 센다.
2. 검출된 자리를 고친다. 아래 방향을 따른다.
   - 엠대시와 띄어 쓴 하이픈 대시는 문장을 완결하고 새 문장으로 잇거나 접속사로 바꾼다. 쌍점으로 바꾸지 않는다.
   - 완결 문장 볼드는 강조를 푼다. 문단을 라벨이 아니라 화제 문장으로 연다.
   - `**라벨**:` 은 라벨 명사를 주어로 세워 뒤 문장과 한 문장으로 합친다. 라벨만 옮긴 머리문장을 따로 두지 않는다. 뒤 문장이 이미 길면 라벨 명사를 그 문장의 주어로만 바꾼다.
   - 개수를 예고하는 헤딩은 개수 대신 내용을 쓴다.
   - 명사구나 연결어미로 끝난 본문 문장은 서술어를 붙여 끝맺는다. 헤딩과 목록은 그대로 둔다.
   - 이모지와 느낌표는 지운다. 프로그램 출력을 인용한 것은 예외다.
   - 부정 대구는 가장 효과적인 하나만 남기고 나머지는 B를 곧바로 단언한다. 전부 지우지는 않는다.
   - 연결어미 뒤 쉼표는 버릇으로 찍은 것만 지운다. 뒷말이 앞 절에 붙어 잘못 읽히는 자리의 쉼표는 남긴다. 500자 넘는 산문에서 쉼표를 다 없애면 계수기가 잡는다.
   - 콜론 부제 헤딩은 명사구 하나로 줄인다.
   - 문단 끝의 당위는 문단 앞이나 중간으로 옮긴다. 지우거나 사실 단정으로 바꾸지 않는다.
   - 분열문은 주어와 서술어를 곧바로 잇는다(`필요한 것은 방향이다`를 `방향이 필요하다`로).
   - 결산 표지는 하나만 남기고 지운다. 인과를 이어야 하면 `그래서`나 접속사 없는 단문으로 쓴다.
   - `단순한 X를 넘어 Y`는 `X만이 아니라 Y다`로 풀거나 Y를 바로 쓴다.
   - 생성형 은유는 은유가 나르던 명제를 문자 그대로 쓴다. 명제를 특정할 수 없으면 그대로 둔다.
   - 반론 문패는 지우고 실제 과제를 첫 문장에 쓴다.
   - 결말부 시간어는 지우거나 원문에 있는 시점과 조건으로 바꾼다. 없는 시점을 지어내지 않는다.
   - 권고 꼬리(`~하시는 것을 권장드립니다`)는 원문의 세기를 지켜 고친다. 권고는 권고로(`~하시기를 권합니다`, `~하는 편이 좋습니다`), 경고는 경고로 남긴다. `~하셔야 합니다`나 명령형 `~하세요`로 올리지도, `~하시면 됩니다`로 낮추지도 않는다. 명령형은 원문이 명령형일 때만 쓴다. 한 글에 같은 꼬리를 되풀이하지 않는다. `~하시기를 권합니다`는 기본값이 아니다. 원문에 조건이 있으면 `~라면 X가 낫습니다`로, 효과가 있으면 `~하면 ~합니다`로 먼저 쓴다.
   - 평가어로 닫은 문장은 원문 안에 있는 결과로 바꾼다. 원문에 결과가 없으면 평가어를 그대로 둔다. 수치나 효과를 지어내지 않는다.
   - 첫머리 예고를 지운 자리에는 원문 안에서 답이 되는 문장을 앞으로 옮긴다. 원문에 없던 요약 문장을 새로 쓰지 않는다.
   - 문장을 고칠 때 주어, 강조(`가장`), 단서(`일반적으로`, `대략`)를 빠뜨리지 않는다. 같은 주어로 세 문장을 잇달아 열지 않는다. 앞 문장의 명사를 지시어와 함께 받아 여는 문장은 그대로 둔다.
   - 주어가 바뀌거나 동작이 셋 넘게 이어지는 문장은 둘로 나누고 둘째 문장을 앞 문장의 말이나 `그래서`로 연다.
   - 쉼표나 연결어미를 줄이려고 긴 문장을 짧은 문장 여럿으로 끊지 않는다.
   - 계수기가 상한 안이라고 통과시킨 문장도 읽어 보고 번역투를 고친다. 피동(`~되어집니다`, `~에 의해`), `~하여`, 문두 `또한`, `~는 것이 효과적입니다`, `~를 통해`처럼 조사 하나로 풀리는 꼴이 대상이다. 계수기 통과는 최소 기준일 뿐이다.
   - 절차와 단계를 안내하는 목록은 구조를 남긴다. `- **1단계**: 서류 준비` 는 볼드만 걷어 `1. 서류를 준비합니다.` 처럼 번호 목록으로 두고, 산문 한 덩어리로 풀지 않는다. 값이 짧은 정의 목록도 같다. 단계 이름을 문장으로 풀 때 원문에 없는 결과를 단정하지 않는다(`**심사 및 실행**` 을 `심사가 끝나면 대출이 실행됩니다` 로 쓰면 승인을 단정한 것이다).
3. 다시 검사해 0 건인지 확인한다.
4. 무엇을 몇 건 고쳤는지만 알린다.

## 하지 말 것

내용을 바꾸지 않는다. 서식과 구조만 다룬다. 사실·이름·숫자·날짜·인용을 더하거나 빼면 안 된다.

서법을 바꾸지 않는다. 추측을 단정으로, 당위를 사실로 올리지 않는다.

한 패턴을 지우면서 다른 패턴을 새로 만들지 않는다. 대시를 없애려고 쉼표를 늘리거나 결말을 다듬다가 대구를 넣으면 실패다. 원문에 없던 결산 표지나 `~하는 이유다` 도치를 새로 만들어도 실패다.

기술 문서에서 관용으로 굳은 비유는 그대로 둔다. 뜻만 남기고 읽는 맛을 없애는 방향으로 고치지 않는다.

인용문과 코드와 프로그램 출력 안의 표현은 건드리지 않는다.
