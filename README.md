# korean-style-guard

한국어 출력에서 AI 티가 나는 서식과 구조를 막고, 지켜졌는지 기계로 검사하는 에이전트 플러그인이다.
주로 문장부호와 마크다운 서식과 문서 구조를 다루고, 실측으로 확인된 어휘 몇 가지와 국어학 연구에 근거한 번역투 기준을 더한다. Claude Code 와
Codex 에서 쓴다.

## 무엇이 들어 있나

## 보칙 31항목

서식 넷, 문장 셋, 구조 다섯, 어휘 여섯, 번역투 여섯, 우리말 다듬기 여섯, 과잉 교정 방지 하나다.

1. 엠대시와 엔대시를 쓰지 않는다. 국립국어원 규정이 인정하는 줄표 용법은 한 쌍으로 쓰는 두 경우뿐이다.
2. 볼드를 아껴 쓴다. 완결 문장을 감싸지 않고, 줄머리에서 문단을 열지 않고, `**라벨**:` 로 서술어를 대신하지 않는다.
3. 이모지와 느낌표와 인사말과 선택지 메뉴를 쓰지 않는다.
4. 연결어미 바로 뒤에 쉼표를 찍지 않는다.
5. 본문 산문은 서술어와 종결어미를 갖춘 완성된 문장으로 끝맺는다. 헤딩과 목록과 표의 칸은 대상이 아니다.
6. 부정 대구(`A가 아니라 B`)는 한 답변에 한 번까지만 쓴다.
7. 여러 문단을 같은 당위로 끝내지 않는다.
8. 헤딩에 개수를 예고하는 틀을 되풀이하지 않는다.
9. 헤딩을 `X: Y` 꼴의 콜론 부제로 되풀이하지 않는다.
10. 무엇을 했는지 밝히지 않은 채 완료 선언으로 보고를 열지 않는다.
11. 묻지 않은 후속 제안으로 글을 닫지 않는다.
12. 같은 작업의 두 번째 보고에서 앞서 낸 표와 문단을 다시 만들지 않는다.
13. 분열문 강조(`필요한 것은 X다`)는 한 답변에 한 번까지만 쓴다.
14. 결산 표지(`결론적으로`, `요컨대`, 논리 결산의 `결국`, `~하는 이유다` 도치)는 한 답변에 한 번까지만 쓴다.
15. `단순한 X를 넘어 Y` 꼴로 격을 올리지 않는다.
16. 사람 글에서 한 번도 나오지 않은 생성형 은유 여덟 가지(`잠식`, `청사진`, `적신호`, `경고등`, `신호탄`, `움켜쥐다`, `뿌리내리다`, `짓누르다`)를 쓰지 않는다.
17. 내용 없이 반론 자리만 거는 문장(`과제도 남아 있다`)을 따로 세우지 않는다.
18. 본문 뒤쪽에서 `향후`, `앞으로`로 문장을 열어 전망을 봉합하지 않는다.
19. 영어 전치사를 옮긴 조사 구(`~에 대해`, `~를 통해`, `~로부터`, `~에 의해`, `~에 있어서`)는 한 답변에 셋까지만 쓴다.
20. 속성을 `가지다`로 쓰지 않는다(`인자를 가지고 있다` 대신 `인자가 셋이다`).
21. 행위자를 밝힐 수 있으면 능동으로 쓰고, 이중 피동(`되어지다`, `보여지다`)은 쓰지 않는다.
22. 수량어 뒤에 복수 `-들`을 겹치지 않는다(`여러 파일들`).
23. 앞 명사를 `그것`, `그들`, `그녀`로 받지 않고 생략하거나 명사를 되풀이한다.
24. `~것이다` 결말은 한 답변에 둘까지, 문두 접속사는 문장 다섯에 하나까지 쓴다.
25. 접미사 `-적`은 셋까지, 조사 뒤 `의`(`에서의`, `와의`)는 한 번까지 쓰고, 관형격 `의`를 세 어절 잇지 않는다.
26. `하다`로 충분한 타동사에 `-시키다`를 붙이지 않는다(`소개시키다`).
27. 영어 과거완료를 옮긴 `-었었-`은 한 번까지만 쓴다.
28. 옮겨 온 관용구(`~에 다름 아니다`, `~을 요하다`, `과언이 아니다`, `가장 ~한 것 중 하나`)를 쓰지 않는다.
29. 겹말(`미리 예약`, `과반수 이상`, `다시 재확인`, `약 3시간 정도`)을 쓰지 않는다.
30. 강조 부사(`매우`, `정말`, `굉장히`)는 둘까지만 쓴다.
31. 규칙을 지키느라 글을 평평하게 만들지 않는다. 고칠 때 서법을 바꾸지 않고, 한 패턴을 지우며 다른 패턴을 새로 만들지 않는다.

1번부터 30번까지가 모두 금지 규칙이므로 31번을 함께 둔다. 지울 대상은 과장과 광고체이고,
구체성은 남긴다.

### 실측에서 가져온 항목의 근거

4·6·7·9항과 13~18항은 [im-not-ai](https://github.com/epoko77-ai/im-not-ai)(MIT)가 사람 글과 AI 글을
대조해 잰 결과에서 가져왔다. 85개 패턴을 다 들이지 않고, 기계로 셀 수 있으면서 사람 쪽이
0건이거나 AI 쪽이 몇 배 많고 모델을 바꿔도 방향이 같았던 것만 골랐다.

| 항목 | 실측 |
|---|---|
| 부정 대구 | 사람 글의 12배. 세 모델과 과업 조건을 바꿔도 유지된 유일한 신호 |
| 연결어미 뒤 쉼표 | KatFish(ACL 2025)에서 사람과 LLM 을 가른 표기 신호. 쉼표 밀도 1.5배 |
| 당위로 끝나는 문단 | 세 모델 모두 사람보다 많았다. 3.7배 |
| 콜론 부제 헤딩 | 같은 저장소의 구조 패턴(C-10) |
| 분열문 강조 | 사람 0.09 대 AI 0.92(1000어절당), 약 10배. 모든 모델과 과업매칭 대조군에서 유지 |
| 결산 표지 | 논리 결산의 `결국`이 사람 0.34 대 AI 1.7. `~하는 이유다` 결말은 사람 1건 대 AI 6편 |
| 범위 상승 | 사람 60편 0건 대 AI 12편 |
| 생성형 은유 여덟 가지 | 사람 532편에서 0건. 가족 합산으로는 4.3배 |
| 반론 문패 | 독립 문장 조건에서 사람 0건 대 AI 8편 |
| 결말부 시간지평 | 본문 뒤쪽 30% 조건에서 사람 0건 대 AI 12편 |

hype 형용사(`혁신적`, `압도적`)는 배수가 1.3배에 그치고
과업을 맞추면 AI 쪽이 0이 되어 뺐다. 계수기는 회계 용어 `자본잠식`처럼 굳은 말을 은유로 세지 않는다.

### 번역투 항목의 근거

19~24항은 기준이 다르다. AI 글을 가리는 신호 대신 자연스러운 한국어를 기준으로 삼는다. im-not-ai 실측에서
`~를 통해`, `~에 대해`, `~것이다` 결말, 문두 접속사는 사람 글(주로 기사와 칼럼)에서 더 많이 나왔다.
그 결과는 기자도 번역투를 많이 쓴다는 뜻일 뿐이고, 이 표현이 자연스럽다는 근거가 되지 못한다. 그래서
판별 실측 대신 국어학과 번역학의 번역투 연구를 근거로 삼았다. 사람 글에도 흔하므로 0건을 요구하지 않고
되풀이만 잡는다.

| 항목 | 근거 |
|---|---|
| 전치사 번역투 | 김정우(2003)는 국어 교과서의 외국어 번역투 가운데 영어 번역투가 유형과 빈도 모두 압도적이고, 그 주된 경로가 구문 형식, 굴절 형식, 전치사구의 전이라고 보고했다. `~로부터`, `~를 통해`, `~에 의해`의 대안은 김정우(2007)와 김순영(2012) |
| 소유 구문 | have 를 `가지다`로만 대응한 예(`목소리를 가지고 있다` → `목소리가 아름답다`). 이근희(2005) |
| 피동과 이중 피동 | 수동태를 직역하면 행위자가 `~에 의하여`로 밀려난다(김정우 1996, 이희재 2009). 이근희(2005)는 비교 말뭉치로 `by` 행위자 표지의 번역투를 추출했다 |
| 중복 복수 | 국어의 `-들`은 수 표시만이 아니라 여럿이 제각각이라는 느낌을 얹는다(김정우 1996) |
| 3인칭 대명사와 접속어 | 영어 번역 한국어에서 인칭대명사와 접속어와 상위어가 우세하다(김정우 2011, 「영어 번역 한국어의 문체와 어휘」) |

무생물 주어(`이 결과는 우리에게 X를 보여 준다`)는 넣지 않았다. 김혜영(2016, 『통번역학연구』 20권 4호)은
영한 번역문과 한국어 비번역문 사이에 무생물 주어 빈도 차이가 통계적으로 유의하지 않았다는 선행 결과를
재확인했다. 번역투로 자주 거론되지만 말뭉치 근거가 약하다.

### 우리말 다듬기 항목의 근거

25~30항도 자연스러운 한국어의 기준이다. 근거는 교정 교열과 글쓰기를 다룬 책이다.

| 항목 | 근거 |
|---|---|
| `-적`, `-의`, `-들` | 김정선, 『내 문장이 그렇게 이상한가요?』(유유, 2016). 단행본을 20년 넘게 교정한 저자가 `적`, `의`, `것`, `들`만 덜어 내도 문장이 나아진다고 정리했다 |
| 조사 뒤 `의`, `-었었-` | 이오덕, 『우리글 바로쓰기』(한길사, 1989~). 우리말 소설들에서 일본식 관형격 `의`와 영어 과거완료 `-었었다`를 작품마다 10~30군데씩 찾았다 |
| `-시키다`, 겹말 | 국립국어원의 다듬은 말과 표준국어대사전 풀이. `과반수`는 이미 절반을 넘는다는 뜻이라 `이상`이 겹친다 |
| 옮겨 온 관용구 | `にほかならない`, `を要する`, one of the most 를 옮긴 꼴. 이오덕(1989) |
| 강조 부사 | 스티븐 킹, 『유혹하는 글쓰기』. 부사는 작가의 자신 없음에서 나온다 |

계수기는 정상 용법을 세지 않는다. `목적`, `지적`, `흔적`처럼 앞이 한 음절인 `-적`, `결과의`, `경로의`처럼
명사 끝 글자가 조사와 같은 꼴, `회의의`, `정의의`처럼 `의`로 끝나는 명사, `이해시키다`처럼 실제 사동은 뺀다.

## 설계 근거

### output style 이 아닌 이유

output style 은 설계상 메인 대화에만 적용된다. 서브에이전트와 헤드리스 실행과 cron 에는
걸리지 않는다. 3항이 겨냥한 것이 정확히 그 경로다.

### SessionStart 훅으로 주입하는 이유

플러그인은 CLAUDE.md 동등물을 배포할 구조가 없다.
`additionalContext` 가 그 자리를 대신하는 유일한 경로다.
matcher 에 `clear` 와 `compact` 를 넣어 두어 `/clear` 뒤에도 다시 주입된다.

### Stop 훅이 필요한 이유

규칙만 적어 두면 지켜지지 않는다. 엠대시를 금지하는 지침이 이미 있어도 계속 나온다.

### 검사 범위

Stop 훅은 대화 답변만 본다. 도구로 쓴 파일은 그 시야 밖이므로 PostToolUse 훅이 맡는다.
`Write` 와 `Edit` 뒤에 방금 쓴 파일을 검사한다.

파일은 종류에 따라 다른 것을 본다. 두 검사의 조건이 정반대라 서로 넘어가지 않게 가른다.

산문 문서는 서식을 본다.

- 확장자가 `.md` `.markdown` `.mdx` `.txt` `.rst` 인 것만 본다
- 한글 비율이 15% 를 넘고 100자 이상인 파일만 본다

코드 파일은 이름을 본다. 보칙 첫 문단이 식별자와 딕셔너리 키와 열거형 값과 파일명을
영문으로 쓰라고 정하는데, 지침만으로는 지켜지지 않아 계수기를 붙였다.

- 파이썬과 자바스크립트 계열, 자바, 코틀린, 스위프트, 다트, C, C++, C#, 고, 러스트,
  PHP, 루비, SQL 을 본다
- 주석과 문자열 리터럴을 지우고 남은 코드에서만 한글을 찾는다
- 파이썬은 표준 `tokenize` 로 지우고, 나머지는 언어별 프로파일을 쓰는 스캐너로 지운다
- 화면에 보이는 글을 위반으로 잡지 않으려고 JSX 텍스트와 문자열 보간과 정규식 리터럴을
  따로 다룬다. 실제 코드베이스 936개 파일에서 오탐 2건이다
- 문자열 안의 한글은 세지 않는다. 한글 딕셔너리 키를 놓치지만, 오탐으로 훅을 꺼 버리게
  만드는 쪽이 더 나쁘다고 봤다

두 검사 모두 `.git` `node_modules` `vendor` `dist` `build` 같은 트리는 건너뛴다.

파일 검사를 끄려면 `KO_STYLE_SKIP_FILES=1` 을 환경 변수로 둔다.
이름 검사만 끄려면 `KO_STYLE_SKIP_IDENTIFIERS=1` 을 둔다.
프로젝트의 기존 관례가 한글 이름인 경우를 위한 스위치다.

## Claude Code 에서 쓰기

세션 안에서 슬래시 명령으로 설치한다.

```
/plugin marketplace add basilro/korean-style-guard
/plugin install korean-style-guard@korean-style-guard
```

터미널에서 CLI 로 해도 된다.

```bash
claude plugin marketplace add basilro/korean-style-guard
claude plugin install korean-style-guard@korean-style-guard
```

갱신할 때는 마켓플레이스를 먼저 새로 받아야 새 버전이 보인다.

```bash
claude plugin marketplace update korean-style-guard
claude plugin update korean-style-guard
```

설치 후 새 세션부터 적용된다.

### 원격 소스로 설치한다

로컬 디렉터리를 마켓플레이스 소스로 등록하면 `Stop` 훅이 등록되지 않는다. 원격에
올린 뒤 그쪽을 소스로 설치한다.

로컬 소스로 개발하는 동안에는 동봉된 `hooks/settings-bridge.sh` 를 쓴다.
`~/.claude/settings.json` 의 `hooks.Stop` 에 걸면 검사가 돈다. 원격 설치라면 필요 없다.

## Codex CLI 에서 쓰기

```bash
codex/install.sh
```

스킬을 `$CODEX_HOME/skills/ko-style/` 에 복사하고 `$CODEX_HOME/hooks.json` 에
`SessionStart` 와 `Stop` 훅을 넣는다. 여러 번 돌려도 중복되지 않는다.
`CODEX_HOME` 을 지정하면 그쪽에 설치한다.

설치 뒤에 한 단계가 남는다. Codex 를 실행해 `/hooks` 에서 두 훅을 신뢰로 표시해야 한다.
승인 전에는 실행되지 않는다.

훅을 직접 넣고 싶으면 `codex/hooks.example.json` 을 참고해 `$CODEX_HOME/hooks.json` 이나
`<repo>/.codex/hooks.json` 에 적는다. 경로는 절대 경로로 쓴다.

`skills/ko-style/agents/openai.yaml` 은 Codex 표면 메타데이터다. 표시 이름과 시작
프롬프트를 담는다.

## 단독 사용

```bash
python3 scripts/ko_style_check.py 파일.md
cat 파일.md | python3 scripts/ko_style_check.py --json
python3 scripts/ko_identifier_check.py 파일.cs
python3 scripts/ko_identifier_check.py 파일.tsx --json
```

위반이 없으면 0, 있으면 1 로 끝난다.
이름 검사기는 확장자로 언어를 가리므로 표준 입력을 받지 않는다.

## 회귀 시험

```bash
python3 tests/run_identifier_tests.py
python3 tests/run_prose_tests.py
```

산문 계수기 시험은 새 항목이 잡아야 할 글과, 사람 글에 흔해서 잡으면 안 되는 글
(`뿐만 아니라`, 명사로 끝나는 `보고,`, 목록 속의 당위)을 함께 둔다.

`tests/cases/` 에 마스킹이 무너지기 쉬운 자리를 골라 30종을 모아 두었다.
JSX 의 화면 글, 문자열 보간, 축자 문자열, 정규식 리터럴, 문법 오류 파일이 여기 든다.
기대값과 그 근거는 `tests/expected.txt` 에 적혀 있다.
이름 검사기를 손보면 이 시험을 먼저 돌린다.

## 전제

Python 3.8 이상. 표준 라이브러리만 쓴다.
